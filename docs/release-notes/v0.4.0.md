Two features and a round of UI fixes. Everything from v0.3.3 still works the
same way, and there is nothing to run after upgrading.

## Version grouping

Searching Civitai for a popular model used to return eight cards all with the
same name. That is not a display bug: one model is published as many versions,
and the provider returns each one as its own result. The version label was the
only thing that differed, and it sat unlabelled in the middle of the meta row.

Versions of one model now collapse into a single card with a version picker,
in **both** Browse and the library. A card marks which versions you already
have, and opens on the one you own rather than the newest — showing you a
version you do not have, when you have another, buries the fact that you own it.

By default, versions built for **different base models stay apart**. A LoRA
rebuilt from SD 1.5 onto SDXL ships as a new version of the same model but is
not a drop-in replacement for it, and hiding it inside the SD 1.5 card's
version list would conceal exactly that. Settings can widen this to group
everything under one model, or turn grouping off entirely.

Bulk actions are unaffected: enrichment still covers every version, not just
the one on screen.

## "Needs update" in the library

The library now marks models with a newer version published upstream, and the
sidebar gains a **Needs update** filter. The mark says which version you have,
which one is newer, and how long ago the check ran — a stored answer shown
without its age reads as freshly checked whether it is a minute or a month old.

The check itself moved from something that ran while you waited to a background
sweep whose result is **saved**. Before, the answer existed only while you
stayed on the Browse tab. Now it survives leaving the tab, closing the browser,
and restarting the daemon — and a daemon started with `--no-remote` can still
show what an earlier check found, even though it will not start a new one.

Nothing stores a "needs update" flag. The database records two facts — which
versions you own, and what the newest one upstream is — and the answer is their
comparison, worked out fresh on every read. That is why downloading an update
clears its mark on its own: once the new file is indexed, the comparison stops
being true. No flag to go stale, and nothing to invalidate.

## Thumbnails and Browse

- Grid thumbnails are **3:4 by default** instead of square. Preview images are
  nearly always portrait — a Civitai preview is usually 512×768 — so a square
  tile cropped the top and bottom off most of the library. Settings offers tall
  (2:3) and square as well.
- The three buttons on a Browse result fit on one line.
- A Browse result with no preview image gets a placeholder tile instead of
  collapsing to a block of text.
- Adult results are **on by default** and remembered, from the Settings tab.
  They were off by default and reset on every reload, so most of what a search
  matched was hidden with no indication that anything had been removed.

## Fixes

- Turning on a filter no longer pushes the sidebar's filter lists down, and the
  type row above the library no longer changes height. Two separate causes, both
  gone: measured at zero pixels of movement.
- The "nsfw" tag on a Browse result was drawn as unreadable pink text on a
  purple block, and the "yours" tag on a preview floated over the picture
  instead of sitting under it.
- The library, Browse and Settings tabs started their content at three
  different offsets, so switching tabs shifted what you were reading.

## Upgrading

One schema migration applies automatically the first time you open the
database. It adds tables, changes nothing existing, and needs no backfill step
from you — the first update check fills them in from responses already
archived, so models enriched long before this release are covered without
re-fetching anything.
