Everything from v0.1.0 still works the same way. This adds control over where
models live and where downloads go, makes the library view stick, and lets
thumbnails be chosen or generated rather than only fetched.

## Upgrading

Two schema migrations apply automatically the first time you open the database.
`model_root` is seeded from the roots already in your index, so nothing needs
doing by hand.

Two optional passes worth running once:

    mm interpret    picks up the base-model split (see below)
    mm thumbs       derives grid-sized copies of previews you already have

## Directories

Add, disable, rescan and forget model directories from the new **Settings** tab,
and scan from the UI with live progress. A directory is canonicalized before it
is stored and one that overlaps an existing root is refused, because the
present-sweep is scoped per root and an overlap makes it ambiguous.

**Forgetting a directory never touches the disk.** It marks the paths absent and
keeps every model record, so re-adding the folder restores what was known rather
than re-deriving it.

## Downloads land in the right folder

Where a download goes is now decided per (directory, model type) rather than
guessed by the browser. Three tools name the same folder three different ways —
a lora is `Lora` under Stability Matrix, `Lora` under SwarmUI and `loras` under
ComfyUI — so a single global mapping was always going to put files where two of
the three would never look. A directory added without a tool set gets one
inferred from its own contents, and the resolved destination is shown before you
press Download.

This also closes a real defect: an unrecognised model type used to be passed
through and pluralized into a directory name, which already produced `vaes/` and
`lycoriss/`. Unknown types now land in the directory itself.

## The library view sticks

Filters are saved server-side, so the view you set up on the desktop is the view
you get on the phone over the tailnet. Type chips sit in the top bar for
one-click visibility, and facet counts now follow the query — they used to
describe the whole library while the list beside them was filtered.

## Thumbnails

Upload your own, pick one from a ComfyUI output folder, or extract the workflow
a ComfyUI PNG carries and get it back as a file. A thumbnail you chose outranks
anything fetched, so enrichment can never displace it.

The grid now serves derived copies capped at 512px — roughly 11× smaller on a
typical render, so a page of forty cards is a few megabytes instead of tens.

## Rendering thumbnails with ComfyUI

Point a base-model family at a workflow you already use — unmodified — and the
app rewrites the lora, the seed and the prompt per model at render time, on a
copy. Your file is never touched. Prompts are traced through the sampler's links
rather than guessed by node order, and the checkpoint and negative prompt are
left alone unless you set them.

The workflow can be a file in ComfyUI's own folder (re-read every render, so
edits take effect with no re-pasting), pasted JSON, or adopted from a rendered
PNG. `mm comfy check` and `mm comfy plan` answer "is this usable" and "what
exactly would be sent" without spending any GPU time.

See `docs/comfyui-workflows.md`.

## Base-model families

Flux.1, Flux.2 and Krea 2 used to collapse into one "Flux" bucket; they are
three architectures needing three different workflows, so they are now three
families. Anima and the SDXL derivatives are recognised properly too, and the
vocabulary is shared between the sidecar, path and header passes — it used to
differ between them, which made a base-model filter quietly wrong.

Labels are derived data, so `mm interpret` re-derives them with no rescan.
