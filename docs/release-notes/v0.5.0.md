The library stops being one machine's. A second copy of Model Manager can now
browse and fetch from the first, and the machine holding the collection can
archive from the providers well enough to outlive them.

Everything from v0.4.2 still works the same way. The three new features are all
off unless you turn them on, and the database upgrades itself on first start.

## One library, several machines

Point one Model Manager at another with `MM_UPSTREAM_URL` and it appears in
Browse beside Civitai, CivArchive and HuggingFace. Search it the same way, see
the same have/new marks against your own disk, and **Pull** a model onto the
machine you are sitting at.

A pulled model lands in the right folder for whichever tool owns that
directory, is verified against the hash the other machine indexed it under, and
is indexed on arrival — the same path a download from a provider takes, because
it is the same path.

This works because a model's identity is its content hash. Two copies of this
program agree on what a model *is* without being told, which is the part that
usually makes syncing hard and here costs nothing.

The metadata comes with it, and so does its history: a name you corrected by
hand on the other machine arrives here as a hand-corrected name, not as
something a later metadata refresh will quietly overwrite. Only the machine
holding the library needs a provider API key, and only it spends the rate
limit.

Serving files is opt-in — `--serve-files` on the machine with the collection.
Off by default, because the default is loopback with no token, where any local
process that can open the port would otherwise have the lot.

## Reclaiming space without losing anything

Pull a model onto a laptop, use it, then **evict** it. The file goes; the name,
tags, previews, provenance and your own edits stay, and the model keeps showing
in the library as available from the machine it came from. Pull it again and it
comes back.

Behind `--allow-evict`, which is deliberately a separate permission from
`--writable`. That flag has always meant "may add things"; deleting a model
file is a different promise, and folding it in would have granted it silently to
every daemon already running.

It refuses in four situations, each of which would otherwise lose something: a
file that was not pulled and so cannot be fetched back, one a download is still
writing, one that has changed since it was indexed, and one that a generated
view links to — where the delete would free no space at all while reporting the
full size, because the view still holds the bytes.

## An archive that survives a takedown

`--allow-archive` turns the collection machine into something that acquires from
the providers rather than only reading what you already have. Archiving a model
keeps the file, the provider's raw responses, every metadata candidate and every
preview image, so a model removed upstream tomorrow is still completely here.

Intake is per model and deliberate. Nothing is crawled.

Because a capture can be interrupted — a rate limit, a preview that is a video
the store will not take, a multi-gigabyte file still transferring — completeness
is recorded part by part. A partial archive says *which* part is missing, and
running it again fetches only the gaps.

A **watchlist** checks the models you care about for new versions, on a timer
you set with `--archive-interval` (six hours by default, `0` to check only when
asked). Fetching a new version automatically is off unless you ask for it: a
watch is a subscription to information, not to unattended multi-gigabyte
downloads.

When a provider stops serving a model, that is recorded and it stops being
re-checked. Before this, a model that 404'd once was asked about on every update
check for the life of the library. Where a mirror still has the record, it is
captured at that moment — the one time a mirror stops being redundant and starts
being the only copy.

## Working with the internet unplugged

The machine holding the collection is the only one that talks to the public
internet, and it now has to keep working when it cannot. Every route that reads
from the library answers from the database and the disk, and every route that
reaches outward fails in a way that says so, rather than looking like an empty
result.

That is checked rather than asserted: the test suite drives the whole API
through a network that refuses every connection, and a route that reads locally
must neither fail nor even attempt to dial.

Two places used to swallow errors and are now honest about them. An unreachable
provider during a search no longer makes models you already own display as new —
which was an invitation to download them again — and an enrichment run with no
network no longer reports zero previews in a way indistinguishable from a
library whose models simply have none.

## Downloads

Free space is checked before a transfer starts, so a download that cannot fit is
refused in the first second with both numbers instead of filling the disk and
leaving a partial behind. Both filesystems are checked: a download is staged
beside the database and only then moved to the model folder, so on the usual
setup it needs room in two places at once.

A resumed download now tells the server which version of the file it already
has. A file that changed mid-transfer restarts cleanly instead of stitching the
old and new halves together into something that only fails at the very end.

And a finished download is read once instead of twice. It used to be hashed to
verify it, then read again in full to record it — 24 GB of reading for a 12 GB
model, on the smallest disks, for the largest files. The copy that lands is also
verified now, which the second read had been doing by accident.

## Upgrading

Nothing to run by hand. The database adds its new tables on first start.

The three new capabilities are each opt-in, and each is announced at startup so
a machine left running with one enabled says so every time:

```
mm serve --writable --serve-files --allow-archive     # the machine with the collection
mm serve --writable --allow-evict                      # a machine that pulls from it
```

with `MM_UPSTREAM_URL`, `MM_UPSTREAM_TOKEN` and optionally `MM_UPSTREAM_NAME`
set on the second. Those live in the environment rather than in Settings on
purpose: a URL the API could write would turn a settings change into "fetch any
address and write the result into a model folder".
