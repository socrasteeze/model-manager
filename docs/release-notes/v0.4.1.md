A two-bug release, both first-run problems introduced in v0.4.0.

## Fixed

**A fresh install told you to go find a terminal.** An empty library showed
"Nothing matches" — answering a question nobody had asked, since nothing had
been searched for yet — followed by instructions to run `mm scan` and
`mm interpret` by hand. Settings has had an **Add directory** field and a
**Rescan everything** button since v0.2.0; the CLI was never the only route,
just the only one the empty state advertised. It's now a setup screen: what
the app is about to do, a note that nothing on disk is touched, and a button
straight onto the Settings tab. The CLI instruction still shows for a
read-only daemon, which genuinely can't add a directory from the UI.

**The owned-version chip in Browse's version picker rendered garbage.** The
check-mark rule was meant to emit a check mark and a non-breaking space, but
a stray escaping bug during the v0.4.0 build turned it into a literal NUL
byte plus junk characters, so every chip for a version you already own showed
`¹3` (or similar) instead of a check mark. Cosmetic only — grouping and the
update badge it decorates were unaffected — but visible on every grouped
Browse result.

## Upgrading

No schema changes and nothing to run by hand.
