A second bugfix release for the "refresh from origin" feature, plus one
internal cleanup. Nothing about how values are merged has changed.

## Fixed

**The per-model refresh button showed even with remote lookups disabled.**
Pressing it under `--no-remote` always failed with no explanation ahead of
time. The button now hides itself when the daemon cannot actually reach an
origin.

**A 409 for a model that just is not on disk blamed an unconfirmed hash.**
Enrichment refuses a model for two different reasons — a provisional path
(the hash itself is unconfirmed) or a path that simply is not present
(moved, deleted, an unmounted drive) — but both used to get the same
"run `mm verify --provisional`" message, which does nothing for the second
case. The two now get their own, accurate message.

**Refreshing one model fetched its full record twice.** Once before the
lookup, to check a preview count nothing else needed; once after, for the
response. Now fetched once.

**Two sweep buttons polled independently.** The library toolbar and Settings
each ran their own poll for progress, so an error from one (most often "a
sweep is already running") could sit under the other's live progress bar and
outlive the run it was about. There is now one shared poll and it clears
itself once it has current truth.

**A finished sweep's summary always read as if it just happened.** It now
says how long ago it ran.

## Changed

`internal/scanjob` and `internal/enrichjob` shared a lot of structure —
same "run at most one job" bookkeeping, same ID generation — under two
independent implementations. That bookkeeping now lives in one place
(`internal/jobrun`), which both compose. No externally visible behavior
change; mentioned here because it's the kind of thing worth knowing moved.

## Upgrading

No schema changes and nothing to run by hand.
